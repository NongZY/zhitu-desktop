# 在 PyCharm 中运行（不需要 Docker）

## 这台电脑的日常启动

1. 用 PyCharm 打开 `E:\项目\学习系统`，不要只打开 `backend` 子目录。
2. 右上角选择 **学习系统（本地，不用 Docker）**，点击绿色运行按钮。
3. 浏览器会自动打开 **http://127.0.0.1:8081**。也可以在浏览器手动输入此地址。
4. 用原账户和原密码登录。第一次打开新地址需要重新登录。
5. 用完后在 PyCharm 点停止按钮。无需启动 Docker，也无需改变虚拟化设置。

如果没有看到运行配置：打开项目根目录的 `run_local.py`，右键选择“运行 run_local”。
不要直接运行 `app/main.py` 或 `models.py`，它们不是完整项目的启动入口。

项目 Python 解释器应为 `E:\项目\学习系统\backend\.venv\Scripts\python.exe`。
如果提示解释器无效，在 PyCharm 的 Python 解释器设置中选择“添加本地解释器 / 选择现有环境”，选中上述文件。

2026-10-19 已在本机 PyCharm 中添加并选中该现有环境；模块继承项目解释器，运行配置使用同一解释器。已直接点击 IDE 的运行按钮验证启动，网页与 `/api/v1/health` 均返回 200。原先绑定的 `Python 3.13 (plan2)` 指向已不存在的文件，是此前 IDE 无法启动的原因。

本次启动前备份保存在 `E:\项目\学习系统备份\pycharm-20261019-184058`，包含原本地数据库、教材副本和启动配置。日常停止请使用 PyCharm 右上角红色停止按钮；不要同时另开第二个实例占用 8081。

## 数据在哪里

- `data/local/learning.db`：账户、密码加密值、章节、题目和学习记录。
- `data/local/uploads/`：教材 PDF 的本地副本。
- `data/local/jwt-secret.key`：本地登录签名密钥，不要公开或上传 GitHub。
- `data/local/migration-*.json`：迁移校验报告，含记录数量及内容摘要，不含明文密码。

本次已按用户确认恢复 **2026 年 10 月 10 日**的数据库备份。该日期之后在 Docker 中新增的内容可能不在本地版本中。
原 Docker 数据、原备份和 `backend/adaptive_learning.db` 均保留，不覆盖、不合并。
两个运行模式的数据之后各自独立，不会自动同步。

备份本地数据时，先停止程序，再复制整个 `data/local` 文件夹。
运行过程中 SQLite 可能生成 `learning.db-wal` 和 `learning.db-shm`，不要在运行时只复制主数据库文件。
密码仍是原加密值，系统不能显示明文密码。

## 阅读位置与继续阅读（2026-10-19）

打开教材，页面图片显示成功后稍等约 1 秒。看到“阅读位置已保存”后，刷新、退出重登或重启程序都能恢复；首页“接着学”会显示最近阅读的教材和 PDF 页码，点击“继续阅读”即可返回。

- “保存中”表示还没收到服务器确认；“位置暂未保存，可重试”表示当前页尚未保存，请点击重试。
- 两个窗口同时读同一本教材，发生位置冲突时点击“重新载入位置”，会采用服务器保存的位置。
- 点击目录或搜索结果可跳页。链接带有效 `page` 时优先打开指定 PDF 页；无指定位置时恢复该账户保存的页。PDF 页码包含封面，可能与印刷页码不同。
- 更换 PDF 内容后会提示重新选择位置；原文件不变、只重新解析目录时仍可恢复。新文件默认页不会直接覆盖旧记录，需要主动选择位置。
- 阅读位置单独保存到当前运行数据库的 `reading_progress` 表，不计入练习时长或知识掌握度。

第一次使用本次新版前，先停止程序并备份整个 `data/local` 文件夹。启动时自动增加 `reading_progress`、`schema_migrations` 两张表，旧账户和学习记录保持原值。多进程部署应先由一个维护进程执行升级，再启动其他进程。

如需回退，停止服务并换回对应的旧代码与网页构建，保留新增表，不要删除原数据库。恢复备份时先恢复到独立副本核对。详细测试结果见 [阅读恢复验收记录](READING_RESUME.md)。

## 本地模式的边界

- 后端和网页由同一个进程提供，地址为 `127.0.0.1:8081`，默认只允许本机使用。
- PDF 解析使用单个后台线程，不再阻塞上传响应；大文件仍需要处理时间。
- 关闭程序会停止服务。正常关闭会等待正在处理的任务；强制终止时，下次启动会提示重新上传，不会永久停在“处理中”。
- SQLite 适合个人本地使用；多人公开部署仍需单独配置数据库、HTTPS、备份和访问控制。
- 保留现有 AI 配置能力，但未配置大模型时使用项目已有的基础问答和练习能力。此次迁移不新增云端 OCR 或模型服务。
- 不会自动创建测试账户，也不会自动导入演示教材。

## 新电脑首次配置（本机已完成，无需重复）

在 PyCharm 中创建 `backend/.venv` Python 3.10+ 环境，安装 `backend/pyproject.toml` 声明的项目及开发依赖。
安装 Node.js，首次在 `frontend` 目录执行 `npm ci`。之后运行 `run_local.py` 会在需要时自动构建网页。
高级参数：`--no-browser` 不自动开浏览器；`--port 8082` 使用其他端口；`--build` 强制更新网页；`--check` 检查基本环境。

如要再次从备份恢复，请先安装可选依赖 `backend[migration]`，使用 `backend/scripts/migrate_local_data.py`，
并选择一个**不存在的新数据库路径**。脚本拒绝覆盖已有数据库；恢复旧快照前应先完整备份当前本地目录。
